# Compute feasibility and zero-cost ladder

| Stage | Scope | Evidence/exit gate |
|---|---|---|
| S0 | Synthetic shapes, probability conservation, masks, grouping fixtures | Future standard-library fixtures only; no medical/model result |
| S1 | Sub-2B matched readout/adaptation pilot | Separately authorized, licensed small model/data, actually free resource and bounded protocol |
| S2 | 2–4B decision/interference replication | Only after S1 signal and free capacity; no automatic escalation |
| S3 | Mid-scale multimodal alignment | Independent image rights/clinical metrics and interface contract |
| S4 | Qwen3.8-27B | Genuinely free qualified allocation bound to exact identity; currently unavailable |
| S5 | Confirmatory flagship | Lawful resources, frozen protocol and qualified review; currently blocked |

Qwen3.5-0.8B-Base and SmolLM2-1.7B are pinned metadata-only small-model candidates in small-model-candidates.json. The latter supplies a distinct Llama-style backbone family for a possible replication; family difference is not evidence of transfer. All pretrained lineages have residual contamination risks. Rounded BF16 weight arithmetic gives about 1.6 GB and 3.4 GB at 0.8B and 1.7B parameters. A hypothetical full-parameter optimizer budget at 16 bytes per parameter is 12.8 GB and 27.2 GB before activations, buffers and runtime overhead. These are design calculations, not measured feasibility. LoRA/head fitting reduces optimizer state but still needs base weights and activations.

No GPU, cloud quota, grant or free compute allocation is bound. No CPU inference feasibility has been measured. Free-tier availability cannot be assumed; stop on any cost-bearing endpoint or capacity request. Resource records must name hardware, allocation duration, billing-disabled configuration, memory/context/batch limits and owner authorization. Jev remains DEFERRED_ZERO_COST_POLICY. No CodeRabbit, Cubic or Qodo qualification is used. No code was introduced, so Alibaba code review is not required.
